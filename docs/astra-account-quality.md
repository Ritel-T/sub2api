# Astra account quality and shared gateway borrowing

This Fork uses one confirmed account classification from the original Astra candy prompt, medium reasoning and expected answer 21. Sol 6.1 and the legacy Sol alias consume that operating classification; they are not independently intelligence-tested. Initial classification uses four completed answers, at least three correct. Periodic classification uses one answer and adds three if it disagrees. Policy changes occur only after the complete round. Authentication, quota, interrupted streams and missing completions are inconclusive quality results and retain separate runtime protections.

The narrow gateway-borrow-policy API uses policy_mode=astra_controls_sol_v2 and credential/proxy/configuration CAS. Existing identity-matched confirmed Astra observations can migrate without a new test. The source pool uses Astra only. New OAuth accounts wait for external defaults to confirm the configured identity and five configuration fields through gateway-borrow-initial-ready; then the existing quality worker performs initial classification. Other configured models remain available while Astra/Sol wait. The minute pending entry and the half-hour cycle share one lock and one policy writer.

Borrowed quality checks use the target account, actual exit and selected Cookie. Turn-state re-signing is not an independent intelligence failure. A target/source combination starts with four Astra answers; proven combinations validate a replacement Cookie with one answer, expanding to four after a wrong answer. The resulting proof is shared between Astra and Sol. New candidate failure keeps any older identity-matched proof until its original expiry. Revalidating the same Cookie never extends its lifetime. Model access, quota, completion, transport and response owner checks remain independent business conditions. No Sol quality experiments or unknown-execution replays are added.

Priority scheduling ignores all OAuth cost/profit estimates and uses confirmed account or current borrowed-route quality, capacity, latency and actual runtime errors. API-key profit behavior and historical financial records are unchanged. Existing sticky/previous-response behavior is preserved; only free account selections use the new capacity ordering. OAuth/API standby remains separately opt-in.

Tested operational sources and their offline regressions are versioned under ops/astra-account-quality. Runtime host paths and backups must be inventoried before deployment; these files are not installers.
