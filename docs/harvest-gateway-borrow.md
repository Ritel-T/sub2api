# 网关借票

入口：智能运维 → 打票流程（`/admin/harvest-flow`）→ 网关借票。默认关闭，卡片默认折叠。手工模式分别选择来源与目标；自动质量模式由质量任务维护账号与模型范围。保存启用后自动获取路由并验证目标。Cookie 与临时探针门票只留在内存，不返回管理接口、不写历史表。

## Sol / Astra 自动质量借票

开启“自动质量借票”后，覆盖 `gpt-6-astra` 与 `gpt-6.1-sol`，`gpt-6-sol` 别名使用 Sol 6.1 的状态。现有定时质量任务需部署相应策略；配置开关本身不运行原生质量检测。自动模式一经启用，面板以只读状态显示，由定时质量任务托管；直接关闭开关并不能停止任务，下一轮会重新启用。管理员停用时须调整任务配置，并先确认受保护模型原生质量恢复；保存借票设置不会清除已确认降智模型的准入保护。

质量任务绕过借票，分别检测每个模型的原生回答。确认降智后，该账号的对应模型进入借票；确认原生恢复正常后退出。限流、网络失败、未完成生成等结果保留之前的分类，不计为质量恢复。借票后的回答不能作为原生已恢复的证据。

自动模式中的来源、目标和目标模型范围只读，刷新配置可查看任务最新结果。它使用按模型的准入保护，不调整套餐分组，也不清除原生限流：Sol 借票失败只保护 Sol，Astra 借票失败只保护 Astra，其他已授权且正常的模型继续使用。无有效借票时，已确认降智的模型请求失败或选择其他可用账号，不落回该账号降智的原生路径。

运行状态按“账号 + 模型”显示；同账号某个模型通过不代表另一个模型通过。Sol / Astra 均按实际模型执行两轮完整生成与稳票验证，通过后使用同一 Cookie 再做四题糖果验收（标准答案 21），全部完整结束且至少三题正确才计为可用；换票、生成失败、模型错误或答错均拒绝。结果只反映当次验证，不证明模型能力永久恢复。覆盖 Sol 表示具备独立验证与保护能力，不代表当前目标的 Sol 已借票成功。账号列表的“需要借票”标签表示原生质量要求，不表示当前存在可用借票。

借票仍使用目标自己的凭据与额度，HTTP Responses 请求不经过 BPS 转换。代理亲和关闭时保留目标自己的出口。手工 WS 固定会话仍为原来的 Astra 功能；自动模式隐藏手工目标、调度接管和固定会话编辑控件，保存其他选项完整保留它们的字段。

设置增加 `auto_quality`、`cookie_pool.models` 和 `cookie_pool.target_models`。最后一项为账号 ID 字符串到模型数组的映射；前端读写深拷贝模型数组，避免草稿修改污染已保存配置。旧配置未提供 `models` 时维持仅 Astra 的行为。

## 原有 Astra 手工模式

来源使用轻量请求取得路由 Cookie。目标复用现有 `openai_codex_state_probe.go` 两轮探针，在借来的 Cookie 与同一出口上使用目标自己的凭据：两次请求都完整成功、续接没有新门票（或回原票），还须使用同一 Cookie 完成四题糖果检测且至少三题正确才可用；新门票、缺票、请求/流失败、路由变化或答错均不可用。验证结果只反映本次路由与答题情况，不代表永久模型能力。手动验证会重新探测，不复用旧的通过状态。

支持来源代理亲和、托管 Mihomo 节点轮换及失败冷却。Astra 使用独立回环端口 17925–17932，与普通打票和 BPS 隔离。路由有效期不因重复使用延长；过期后重新获取和验证。无可用路由时拒绝目标借用，不自动退回未验证出口。

可选 WS 固定会话按 API Key、分组、账号和客户端会话隔离；后续请求必须提供响应 ID 并继续使用原连接。借票不复制来源账号的凭据或门票，也不替代普通打票的账号范围和门票策略。

可选号池调度在目标探针通过且路由有效时恢复本功能拥有的变更；否则按设置暂停账号、屏蔽 Astra 模型或移出指定分组。只修改所选目标，切换模式先恢复旧动作，遇到人工编辑冲突不覆盖。关闭接管保留当时状态。仅切换调度设置不清空已验证路由。

新增 `astra_gateway_history` 和 `astra_scheduling_states` 两张表；保留原私有版本迁移文件名和内容，已有实例可兼容。历史通过不代表当前可用。启用后会发送来源获取和目标探针请求；页面读取状态不触发请求。
