# 订阅额度耗尽后的按量接续

管理员在「分组管理」的订阅分组中选择「额度耗尽后按量接续分组」。目标必须是同平台、启用中的标准按量分组；源和目标均不支持 Composite 分组，避免跨组模型别名与路由产生歧义；留空表示仍按原行为拒绝超额请求。API 字段为 `subscription_fallback_group_id`，创建时可省略或传 null，更新时省略保持、传 0 清除。

只有仍有效的订阅达到日、周或月用量上限才启用接续。无订阅、订阅过期或停用、API Key 到期或额度耗尽、用户停用、权限失败、后台不可用不会因此被放行。目标分组的可用状态、平台与用户访问权限会重新检查。

接续不永久重绑 Key。接续请求使用目标分组调度、模型权限与按量价格，使用该用户在目标分组的专属倍率；没有专属倍率时使用目标默认倍率。实际费用从用户余额扣除，仍受 Key 总限额、周期限额、用户平台额度及并发限制约束；不增加原订阅用量。余额不足时停止。订阅额度恢复且订阅仍有效后，新请求自动恢复订阅计费。

已建立的 Responses WebSocket 不能携带旧账号跨分组切换。检测到计费分组需要变化时，连接返回可重试的配置变化错误；客户端重新连接后使用新的计费分组，不自动重放已发送的请求。

普通生成类 HTTP 请求在并发等待结束、选择上游账号之前重新确认计费分组，并同时遵守原订阅组和接续组的模型、用户限制及内容审核。需要切换时，同一个尚未发往上游的请求即可按新分组执行。计数请求保持原有不记录用量的行为，不产生扣费通知。

OpenAI Live 暂不支持订阅按量接续：该入口目前没有完整的实际费用扣款流程。已在接续状态的握手直接返回 `403 subscription_fallback_unsupported`；排队期间订阅额度耗尽也在创建 Live 会话前拒绝。仍有有效订阅额度的既有 Live 行为保持不变。Grok Voice 普通 HTTP 生成与转录支持上述接续；Grok Realtime 沿用会话结束时的音频计费，不在已经连接的会话中迁移分组。

缓存内容的创建可在绑定账号之前选择接续组；既有缓存资源的查询、修改和删除保留原账号与分组绑定，不能借接续迁移资源。已有绑定资源和实时会话需要变更计费分组时，遵循各入口的拒绝或重新连接机制。


首次实际按量扣费与通知记录在同一数据库事务中落库。邮件包含订阅组、耗尽周期、接续组、实际倍率、该次扣费和扣费后余额。同一用户、订阅、耗尽维度和周期起点只生成一次通知，跨进程与并发请求不会重复生成。邮件由后台发送；明确未进入投递的失败有限重试，投递结果未知时保留状态而不自动重复发送。管理员可沿用邮件通知设置和模板管理配置内容。

订阅月限额与周限额是独立数值。月限额设为周限额的四倍不会更改既有月窗口的长度、开始时间或已使用金额。公开标准分组使用 `is_exclusive=false`；用户显式限制公开分组访问时，仍遵守原授权规则。

购买与续订卡片的关联分组名称、倍率和日、周、月额度从分组当前设置读取，无需复制到商品卖点中；刷新页面后展示更新的设置。商品名称、价格、购买时长和普通卖点由套餐自身配置。明确写了日、周、月额度的旧手写卖点会被隐藏，以结构化额度为准；额度为零或未设置表示该周期没有上限。关联分组停用、删除或改为非订阅类型时，商品不再出现在购买列表，后台保留商品供管理员修复。

Responses HTTP 的 `previous_response_id` 继续绑定生成该响应的用户、Key 和分组。计费分组变化不会迁移已有响应；若续接所属分组不匹配，请使用完整历史发起新请求。
